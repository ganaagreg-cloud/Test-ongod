## Problems / blockers

- Push has not reached a phone: it needs a new dev build (new native module), an EAS project, a Firebase project with an FCM key (Android) and an APNs key (iOS, paid Apple Developer Program) ([[MOBILE_BUILD]], [[DEVICE_SMOKE]] row 35).
- The global rate limit (`RATE_LIMIT_MAX`, 300 per minute per IP) also counts the static files of the admin and portal (92 of 316 requests in the failing minute). A fast admin, the admin e2e, or many people behind one address reach it; a reload then cannot renew the session and shows the login screen. Proposal: count `/v1` only (needs an ADR).
- Later the same day: the global rate-limit problem above is fixed by ADR-0057. Static files now have no limit in the app; flood protection is left to the host (TO-VERIFY, [[R-hosting-limits]]).
- Payment history on Миний бүртгэл (in mockup A) is not built: the API has no list of a member's own payments; needs an endpoint and a decision.
- Comments on episodes conflict with [[SPEC]] (out of scope); app store rules for user comments are not researched yet (TO-VERIFY, no note).
- Each admin e2e run leaves one switched-off test plan in the local database (plans cannot be deleted by design).
- The dashboard income counts payments, and a gift payment is created when it is redeemed, not bought; the Бэлэг page shows the unredeemed amount. Count gifts at purchase only if the owner asks.
- Comments are not store-ready: `SUPPORT_EMAIL` is empty (open question #26 decides the contact) and the Google Play rule text is unread ([[R-store-ugc-rules]], [[LAUNCH_CHECKLIST]]). `support.google.com` and `play.google.com` need to be allowed in the session network to finish the note.
- Ganaa: there is no support email yet, so `SUPPORT_EMAIL` stays empty and the app hides comments ([[ADR-0061-episode-comments|ADR-0061]], [[open-questions]] #26). The Google Play rule is still unread: `support.google.com` is not allowed in the session network ([[R-store-ugc-rules]]).
- A store build needs a published contact (`SUPPORT_EMAIL`): nothing in the code stops it now, only [[LAUNCH_CHECKLIST]].
- Expo SDK 58 (`expo` 58.0.19, `react-native` 0.88) declares Node `^22.13 || ^24.3 || >=26`, but `.nvmrc` and CI use Node 20 and CLAUDE.md says Node 20. CI installs and typechecks on Node 20 (`0b017f0`), but Metro and the native builds are not supported there. Needs a decision (an ADR): Node 22 for the mobile tooling and CI, the API host staying on what iTools offers ([[R-hosting-limits]], TO-VERIFY).
- `claude/youthful-johnson-eat3vk` on GitHub still ends at `0b017f0` with the failed CI; the fixed state is on `claude/dreamy-dijkstra-cag0it`.
