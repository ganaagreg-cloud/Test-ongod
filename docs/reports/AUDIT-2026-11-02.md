## Not verified / deliberately outside scope

- **Background timer accuracy on iOS/Android is NOT verified; it needs a phone.** Foreground and simulated native-resume behavior are tested with a fake engine/clock; these tests do not certify native lock-screen or suspended-JS timing.
- Real Bunny playback/uploads, real payments, production hosting and browser/native E2E were not exercised; API media tests use local storage and a fake Stream client with real MySQL transactions.
- Separate question, **not part of this task**: whether URL expiration can interrupt a long episode. `PLAY_URL_TTL_MS` in `apps/api/src/catalog/media.ts` is **four hours**. The actual signed URL expiry is the minimum of that TTL and the member's access end (or the full TTL without active access for a free item). A roughly **1h40** episode does not outlive a fresh four-hour URL by duration alone. Episodes longer than four hours, delayed starts/long pauses, slower playback or a shorter remaining access period can outlive the issued URL. No renewal-during-playback was built; CDN/native behavior at URL expiry was not tested.
- Payment reconciliation's newest-50 limitation remains the existing accepted tradeoff in [[ADR-0047-wire-payment-sync-window]], outside R10–R13. Reminder pagination is deliberately bounded to five pages, not an unlimited scan.
