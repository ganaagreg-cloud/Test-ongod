## Findings, most important first

1. **The member side of the app is not built.** The mobile app has the sign-in screens, the start-up gate, the update screen, the UI kit (`/dev/ui`) and an audio bench (`/dev/audio`). After login it shows a placeholder. Not built: tabs, Нүүр / Сан / categories, episode + player screen ([[ADR-0028-cream-library-and-16x9-artwork|ADR-0028]]: player = episode), mini player, Хадгалсан, profile and settings (change password / email, devices, legal links), **in-app account deletion** (a store requirement, [[R-account-deletion-stores]]), the no-access state ([[SPEC]] F), push registration (`expo-notifications` is not installed). The API for all of these exists and is tested.
2. **No build has ever run on a phone.** The device gate ([[ADR-0015-local-first-android-smoke-test|ADR-0015]], [[DEVICE_SMOKE]]) is Android-only and still open. No audio from this code has played on hardware.
3. **iOS first conflicts with [[ADR-0015-local-first-android-smoke-test|ADR-0015]]** (Android gate) and with the client's 30% milestone ([[approvals]]: "week-4 Android demo"). Needs a new ADR and a word to the client.
4. **Cover pipeline still makes square covers** (`apps/api/src/media/cover.ts`, [[ADR-0021-catalog-and-playback-rules|ADR-0021]] item 5: 1400×1400 centre crop), but [[ADR-0028-cream-library-and-16x9-artwork|ADR-0028]] says episode pictures are 16:9. A 1280×720 thumbnail loses its sides today. Fix (with a new ADR replacing ADR-0021 item 5) before real content is uploaded.
5. **Registration deadlock still open** (found 2026-10-09): `issueCode` in `apps/api/src/auth/service.ts` can deadlock on two registrations at once and answer 500. No `P2034` retry, no test.
6. **Two broken API tests** (`apps/api/test/admin-uploads.test.ts`): the "missing episode → 404" case sends the file as field `receipt` (helper default) instead of `cover`, so it gets 400 `COVER_INVALID`; the "decompression bomb" case cannot build its 400-megapixel fixture under sharp 0.35's default pixel limit (needs `limitInputPixels: false` in the test). Product code is fine in both.
7. **No CI.** There is no `.github/workflows`; nothing runs the checks on push. The API suite went unrun for over a week and the two broken tests slipped through.
8. **Playback needs Bunny.** Without `BUNNY_*` the API returns no audio URL and no covers (`apps/api/src/catalog/media.ts`). Any audio test on a phone needs the Bunny dev zone ([[ADR-0005-bunny-dev-zone-env-switch|ADR-0005]], [[BUNNY_SWITCH]]).
9. **Phone → API over plain http (TO-VERIFY on iOS).** The runbooks point the phone at `http://<PC LAN IP>:3000`. iOS builds may block plain http (App Transport Security) and ask for Local Network access. A staging API on https avoids both.
10. Still unverified on a device: the Apple sign-in nonce ([[R-expo-apple-authentication]]), Google iOS client IDs, SecureStore, lock-screen controls (fixed at 10 s jumps, [[R-expo-audio-sdk57]]).
